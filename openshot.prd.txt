사용자가 정의한 **JSON 데이터를 기반으로 일본어 루비(요미가나) 자막이 포함된 OpenShot 프로젝트(`.osp`)를 자동 생성**하는 파이프라인 구축을 위한 PRD(제품 요구 사양서) 초안입니다.

이 계획은 OpenShot의 GUI에서 노가다를 하는 대신, **템플릿 기반의 자동화 엔진**을 구축하는 데 초점을 맞춥니다.

---

## [PRD] Japanese Subtitle Automation Pipeline for OpenShot

### 1. 프로젝트 개요

* **목표**: 비디오, 오디오, JSON 자막 데이터를 결합하여 루비 태그가 적용된 투명 PNG 자막을 생성하고, 이를 OpenShot 타임라인에 자동 배치하는 Python 스크립트 개발.
* **핵심 가치**: 일본어 요미가나 작업의 수동 편집 시간을 90% 이상 단축하고, 일관된 자막 디자인 유지.

---

### 2. 시스템 아키텍처 (Workflow)

1. **Template Layer**: 자막의 스타일(CSS), 폰트, 위치를 정의하는 HTML/CSS 템플릿.
2. **Generator Layer**:
* **Playwright Engine**: JSON 데이터를 읽어 HTML로 변환 후 투명 PNG 렌더링.
* **Asset Loader**: 비디오/오디오 파일을 스캔하여 시퀀스 생성.


3. **Integrator Layer (OSP Builder)**: 모든 에셋을 OpenShot의 JSON 스키마(`.osp`)에 맞춰 결합.

---

### 3. 주요 구성 요소 상세 사양

#### 3.1. 자막 디자인 템플릿 (CSS-based)

OpenShot의 내부 템플릿 대신 **HTML/CSS를 마스터 템플릿**으로 사용합니다.

* **폰트**: Noto Sans JP (혹은 지정 폰트) 적용.
* **루비 태그**: `ruby rt { font-size: 0.5em; vertical-align: top; }` 등 세부 조정.
* **가이드**: 1920x1080 해상도 전체를 캔버스로 잡고, 우측 상단에 자막 바를 고정 배치하여 OpenShot에서 별도의 좌표 조정이 필요 없게 설계.

#### 3.2. 자막 생성기 (Python + Playwright)

* **Input**: 제공된 대화형 JSON 데이터.
* **Logic**:
* `text` 내의 한자를 `kanjis` 정보를 참조하여 `<ruby>` 태그로 치환.
* Playwright의 `screenshot(omit_background=True)`를 이용해 투명 PNG 생성.


* **Output**: `subs/sub_001.png`, `sub_002.png` ...

#### 3.3. OpenShot 프로젝트 생성기 (OSP Logic)

OpenShot 프로젝트 파일(`.osp`)은 JSON 구조이므로, 다음 로직을 자동화합니다.

| 레이어(Track) | 내용 | 비고 |
| --- | --- | --- |
| **Layer 3 (Top)** | **자막 PNG** | JSON의 `start`, `end` 값을 `position`과 `duration`으로 환산 배치 |
| **Layer 2** | **오디오** | 이름 순서대로 배치 (이전 파일의 종료점이 다음 파일의 시작점) |
| **Layer 1** | **비디오** | 이름 순서대로 배치 (길이는 일단 파일 정보 로딩) |

---

### 4. 개발 진행 순서 (Roadmap)

#### Step 1: 베이스 프로젝트 추출

1. OpenShot을 켜고 **샘플 비디오 1개, 오디오 1개, 자막용 PNG 1개**를 타임라인에 올립니다.
2. 자막의 위치와 크기를 잡은 후 프로젝트를 저장(`.osp`)합니다.
3. 이 파일을 텍스트 에디터로 열어 `files`와 `clips` 섹션의 데이터 구조를 파악합니다. (이것이 파이썬 스크립트의 **JSON 템플릿**이 됩니다.)

#### Step 2: Playwright 렌더링 스크립트 완성

* JSON을 순회하며 `<ruby>` 태그가 적용된 HTML을 PNG로 뽑아내는 모듈을 완성합니다.
* 이때 이미지 크기는 1920x1080으로 고정하여, OpenShot에 임포트 시 별도 위치 조정이 필요 없게 만듭니다.

#### Step 3: OSP JSON 조작 스크립트 작성

* `files` 배열에 생성된 모든 PNG, 비디오, 오디오의 경로와 속성을 주입합니다.
* `clips` 배열에 각 파일이 타임라인 어디에 놓일지 계산하여 넣습니다.
* `position`: 타임라인 시작 시점 (초)
* `start`: 소스에서의 시작 시점 (0)
* `end`: 소스에서의 종료 시점 (파일 길이 혹은 자막 데이터의 `end`)



#### Step 4: 최종 테스트 및 수동 편집

* 생성된 `.osp` 파일을 OpenShot에서 로드합니다.
* 자동으로 배치된 자막과 미디어를 확인하고, 필요한 경우 인간이 미세 조정을 진행합니다.

---

### 5. 기술적 도전 과제 및 해결 방안

* **오디오/비디오 길이 파악**: `ffprobe` (ffmpeg)를 사용해 파이썬에서 미디어 파일의 정확한 길이를 가져와 `end` 값에 주입해야 합니다.
* **레이어 순서**: OpenShot은 숫자가 높을수록 상단 레이어입니다. 자막을 가장 높은 숫자의 트랙에 배치해야 합니다.
